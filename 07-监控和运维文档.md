# TiDB 监控和运维文档

## 1. 监控体系概述

### 1.1 监控架构

#### 1.1.1 整体监控架构

TiDB 采用多层次的监控架构：

```
┌─────────────────────────────────────────────────────────────────┐
│                      监控展示层                                │
│  • Grafana Dashboard                                          │
│  • Alertmanager 告警                                           │
│  • 自定义监控面板                                              │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                     数据收集层                                 │
│  • Prometheus 指标收集                                         │
│  • 日志收集 (Fluentd/ELK)                                     │
│  • 分布式追踪 (Jaeger)                                         │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                     指标导出层                                 │
│  • TiDB Exporter                                              │
│  • TiKV Exporter                                              │
│  • PD Exporter                                                 │
│  • TiFlash Exporter                                            │
│  • Node Exporter                                               │
└─────────────────────────────────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│                     TiDB 集群                                 │
│  • TiDB Server                                                 │
│  • TiKV Server                                                 │
│  • PD Server                                                   │
│  • TiFlash Server                                              │
└─────────────────────────────────────────────────────────────────┘
```

#### 1.1.2 监控组件

**核心组件**：
- **Prometheus**：时序数据库，存储和查询监控指标
- **Grafana**：可视化监控面板
- **Alertmanager**：告警管理和通知
- **Exporter**：指标导出器

**监控指标类型**：
- **业务指标**：QPS、延迟、错误率
- **资源指标**：CPU、内存、磁盘、网络
- **集群指标**：Region 状态、Raft 状态
- **性能指标**：查询性能、锁等待、热点信息

## 2. Grafana 监控面板

### 2.1 预置面板介绍

#### 2.1.1 Overview 面板

**集群概览指标**：
- **集群状态**：节点在线状态
- **QPS**：读写 QPS 统计
- **延迟**：查询响应时间
- **错误率**：查询错误统计
- **连接数**：活跃连接数

**关键监控项**：
```sql
-- QPS 监控查询
SELECT
    SUM(read_query_count) as read_qps,
    SUM(write_query_count) as write_qps,
    SUM(read_query_count + write_query_count) as total_qps
FROM information_schema.TIDB_METRICS_TABLE
WHERE TIME >= NOW() - INTERVAL 5 MINUTE;

-- 延迟监控
SELECT
    AVG(query_time) as avg_query_time,
    MAX(query_time) as max_query_time,
    PERCENTILE(query_time, 95) as p95_query_time
FROM information_schema.CLUSTER_SLOW_QUERY
WHERE TIME >= NOW() - INTERVAL 5 MINUTE;
```

#### 2.1.2 TiDB 面板

**TiDB Server 监控**：
- **连接信息**：活跃连接数、总连接数
- **查询统计**：查询类型分布、执行时间
- **事务信息**：事务数量、事务延迟
- **DDL 信息**：DDL 执行状态

**重要指标**：
```sql
-- 连接监控
SELECT
    COUNT(*) as active_connections,
    COUNT(DISTINCT user) as active_users
FROM information_schema.PROCESSLIST;

-- 查询类型统计
SELECT
    SUM(CASE WHEN query_type = 'SELECT' THEN 1 ELSE 0 END) as select_count,
    SUM(CASE WHEN query_type = 'INSERT' THEN 1 ELSE 0 END) as insert_count,
    SUM(CASE WHEN query_type = 'UPDATE' THEN 1 ELSE 0 END) as update_count,
    SUM(CASE WHEN query_type = 'DELETE' THEN 1 ELSE 0 END) as delete_count
FROM information_schema.TIDB_METRICS_TABLE;
```

#### 2.1.3 TiKV 面板

**TiKV Server 监控**：
- **存储信息**：存储使用量、Region 数量
- **Raft 状态**：Leader 数量、选举信息
- **读写流量**：读写流量统计
- **资源使用**：CPU、内存、磁盘 I/O

**存储监控**：
```sql
-- 存储使用情况
SELECT
    store_id,
    capacity,
    available,
    used_size,
    leader_count,
    region_count
FROM information_schema.TIDB_STORE_STATUS;

-- Region 状态
SELECT
    COUNT(*) as total_regions,
    SUM(CASE WHEN is_leader = 1 THEN 1 ELSE 0 END) as leader_regions,
    SUM(CASE WHEN is_pending = 1 THEN 1 ELSE 0 END) as pending_regions
FROM information_schema.TIDB_REGION_STATUS;
```

#### 2.1.4 TiFlash 面板

**TiFlash 监控**：
- **副本状态**：副本同步状态
- **查询性能**：查询执行时间、内存使用
- **存储压缩**：压缩比、存储效率
- **数据同步**：同步延迟、进度

**TiFlash 监控查询**：
```sql
-- TiFlash 副本状态
SELECT
    table_name,
    COUNT(*) as region_count,
    SUM(CASE WHEN available = 1 THEN 1 ELSE 0 END) as available_count,
    AVG(progress) as sync_progress
FROM information_schema.TIFLASH_REPLICA_STATUS
GROUP BY table_name;

-- TiFlash 查询性能
SELECT
    AVG(query_time) as avg_query_time,
    MAX(memory_usage) as max_memory_usage,
    COUNT(*) as query_count
FROM information_schema.TIFLASH_QUERY_METRICS
WHERE timestamp >= NOW() - INTERVAL 1 HOUR;
```

### 2.2 自定义面板

#### 2.2.1 创建自定义面板

**业务监控面板**：
```sql
-- 业务 QPS 监控
SELECT
    HOUR(created_at) as hour,
    COUNT(*) as order_count,
    SUM(total_amount) as total_amount
FROM orders
WHERE created_at >= CURDATE()
GROUP BY HOUR(created_at)
ORDER BY hour;

-- 用户活跃度监控
SELECT
    DATE(created_at) as date,
    COUNT(DISTINCT user_id) as active_users,
    COUNT(*) as actions
FROM user_actions
WHERE created_at >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
GROUP BY DATE(created_at)
ORDER BY date;
```

**性能监控面板**：
```sql
-- 慢查询分析
SELECT
    HOUR(start_time) as hour,
    COUNT(*) as slow_query_count,
    AVG(query_time) as avg_time,
    MAX(query_time) as max_time
FROM information_schema.CLUSTER_SLOW_QUERY
WHERE start_time >= CURDATE()
GROUP BY HOUR(start_time)
ORDER BY hour;

-- 热点表监控
SELECT
    table_name,
    SUM(read_count) as total_reads,
    SUM(write_count) as total_writes,
    SUM(read_count + write_count) as total_access
FROM information_schema.TABLE_ACCESS_STATS
GROUP BY table_name
ORDER BY total_access DESC
LIMIT 10;
```

## 3. 告警系统

### 3.1 告警规则配置

#### 3.1.1 基础告警规则

**集群状态告警**：
```yaml
# alert_rules.yml
groups:
  - name: tidb_cluster
    rules:
      # TiDB 节点离线
      - alert: TiDBNodeDown
        expr: up{job="tidb"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "TiDB 节点 {{ $labels.instance }} 离线"
          description: "TiDB 节点 {{ $labels.instance }} 已离线超过 1 分钟"

      # TiKV 节点离线
      - alert: TiKVNodeDown
        expr: up{job="tikv"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "TiKV 节点 {{ $labels.instance }} 离线"
          description: "TiKV 节点 {{ $labels.instance }} 已离线超过 1 分钟"

      # PD 节点离线
      - alert: PDNodeDown
        expr: up{job="pd"} == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "PD 节点 {{ $labels.instance }} 离线"
          description: "PD 节点 {{ $labels.instance }} 已离线超过 1 分钟"
```

**性能告警**：
```yaml
  - name: tidb_performance
    rules:
      # 高延迟查询
      - alert: HighQueryLatency
        expr: histogram_quantile(0.95, rate(tidb_executor_statement_duration_seconds_bucket[5m])) > 1
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "查询延迟过高"
          description: "95% 的查询延迟超过 1 秒，当前值为 {{ $value }} 秒"

      # 连接数过多
      - alert: TooManyConnections
        expr: tidb_server_connections > 1000
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "连接数过多"
          description: "当前连接数 {{ $value }} 超过阈值 1000"

      # 慢查询过多
      - alert: TooManySlowQueries
        expr: rate(tidb_server_slow_query_total[5m]) > 10
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "慢查询过多"
          description: "当前慢查询率 {{ $value }} 次/秒超过阈值"
```

#### 3.1.2 资源告警

**资源使用告警**：
```yaml
  - name: tidb_resource
    rules:
      # CPU 使用率过高
      - alert: HighCPUUsage
        expr: 100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "CPU 使用率过高"
          description: "{{ $labels.instance }} CPU 使用率 {{ $value }}% 超过 80%"

      # 内存使用率过高
      - alert: HighMemoryUsage
        expr: (1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100 > 85
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "内存使用率过高"
          description: "{{ $labels.instance }} 内存使用率 {{ $value }}% 超过 85%"

      # 磁盘空间不足
      - alert: LowDiskSpace
        expr: (1 - (node_filesystem_avail_bytes / node_filesystem_size_bytes)) * 100 > 85
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "磁盘空间不足"
          description: "{{ $labels.instance }} 磁盘 {{ $labels.mountpoint }} 使用率 {{ $value }}% 超过 85%"
```

## 5. 性能监控

### 5.1 关键性能指标

#### 5.1.1 QPS 和延迟监控

**QPS 监控查询**：
```sql
-- 实时 QPS 监控
SELECT
    TIME_FORMAT(TIMESTAMP, '%H:%i') as time_slot,
    SUM(CASE WHEN query_type = 'SELECT' THEN 1 ELSE 0 END) as select_qps,
    SUM(CASE WHEN query_type = 'INSERT' THEN 1 ELSE 0 END) as insert_qps,
    SUM(CASE WHEN query_type = 'UPDATE' THEN 1 ELSE 0 END) as update_qps,
    SUM(CASE WHEN query_type = 'DELETE' THEN 1 ELSE 0 END) as delete_qps
FROM information_schema.TIDB_METRICS_TABLE
WHERE TIMESTAMP >= NOW() - INTERVAL 1 HOUR
GROUP BY TIME_FORMAT(TIMESTAMP, '%H:%i')
ORDER BY time_slot;

-- 数据库级别的 QPS
SELECT
    table_schema,
    SUM(read_query_count) as read_qps,
    SUM(write_query_count) as write_qps,
    SUM(read_query_count + write_query_count) as total_qps
FROM information_schema.TABLE_ACCESS_STATS
GROUP BY table_schema
ORDER BY total_qps DESC;
```

**延迟监控查询**：
```sql
-- 查询延迟分布
SELECT
    COUNT(*) as query_count,
    AVG(query_time) as avg_time,
    MIN(query_time) as min_time,
    MAX(query_time) as max_time,
    PERCENTILE(query_time, 50) as p50_time,
    PERCENTILE(query_time, 95) as p95_time,
    PERCENTILE(query_time, 99) as p99_time
FROM information_schema.CLUSTER_SLOW_QUERY
WHERE start_time >= NOW() - INTERVAL 1 HOUR;

-- 按查询类型统计延迟
SELECT
    query_type,
    COUNT(*) as query_count,
    AVG(query_time) as avg_time,
    MAX(query_time) as max_time
FROM information_schema.CLUSTER_SLOW_QUERY
WHERE start_time >= NOW() - INTERVAL 1 HOUR
GROUP BY query_type
ORDER BY avg_time DESC;
```

#### 5.1.2 热点监控

**热点 Region 监控**：
```sql
-- 读写热点 Region
SELECT
    table_name,
    region_id,
    read_bytes,
    write_bytes,
    read_keys,
    write_keys,
    read_query_count,
    write_query_count
FROM information_schema.TIDB_HOT_REGIONS
ORDER BY read_bytes + write_bytes DESC
LIMIT 10;

-- 热点表监控
SELECT
    table_name,
    SUM(read_count) as total_reads,
    SUM(write_count) as total_writes,
    SUM(read_count + write_count) as total_access,
    AVG(read_latency) as avg_read_latency,
    AVG(write_latency) as avg_write_latency
FROM information_schema.TABLE_ACCESS_STATS
GROUP BY table_name
ORDER BY total_access DESC
LIMIT 10;
```

### 5.2 性能分析工具

#### 5.2.1 执行计划分析

### 6.1 容量规划

#### 6.1.1 数据增长监控

    SUM(index_length) as index_size

    table_rows,
    ROUND(data_length / 1024 / 1024, 2) as data_size_mb,

**容量预测**：
```sql
-- 基于历史增长预测
WITH growth_data AS (
    SELECT
        DATE_FORMAT(created_at, '%Y-%m') as month,
        SUM(data_length + index_length) as total_size
    FROM information_schema.TABLES
    WHERE table_schema = 'your_database'
    GROUP BY DATE_FORMAT(created_at, '%Y-%m')
)
SELECT
    month,
    total_size,
    LAG(total_size, 1) OVER (ORDER BY month) as prev_size,
    total_size - LAG(total_size, 1) OVER (ORDER BY month) as growth,
    (total_size - LAG(total_size, 1) OVER (ORDER BY month)) / LAG(total_size, 1) OVER (ORDER BY month) * 100 as growth_rate
FROM growth_data
ORDER BY month;
```

### 6.2 扩容决策

#### 6.2.1 扩容指标

**扩容触发条件**：
- **存储使用率 > 80%**
- **CPU 使用率 > 70% 持续 30 分钟**
- **内存使用率 > 85%**
- **查询延迟超过阈值**

**扩容计算**：
```bash
# 计算所需节点数量
current_nodes=3
total_size=1000  # GB
usage_percent=85
new_usage_target=60

required_size=$(echo "scale=2; $total_size * $usage_percent / 100 / $new_usage_target" | bc)
current_node_capacity=$(echo "scale=2; $required_size / $current_nodes" | bc)
required_nodes=$(echo "scale=0; ($required_size / $current_node_capacity + 0.5)/1" | bc)

echo "当前节点数: $current_nodes"
echo "所需节点数: $required_nodes"
echo "需要增加: $(($required_nodes - $current_nodes)) 个节点"
```

#!/bin/bash

# TiDB 自动备份脚本

    --pd "127.0.0.1:2379" \

    --single-transaction \
    --routines \
    --triggers \

# 压缩备份
echo "压缩备份文件..."
cd $BACKUP_DIR
tar -czf $DATE.tar.gz $DATE/
rm -rf $DATE/

# 清理旧备份
echo "清理 ${RETENTION_DAYS} 天前的备份..."
find $BACKUP_DIR -name "*.tar.gz" -mtime +$RETENTION_DAYS -delete

#### 7.1.2 健康检查脚本

**集群健康检查**：
```bash
#!/bin/bash

# TiDB 集群健康检查脚本
CLUSTER_NAME="tidb-cluster"
ALERT_EMAIL="admin@example.com"

# 检查函数
check_component() {
    local component=$1
    local expected_count=$2

    actual_count=$(tiup cluster display $CLUSTER_NAME | grep "$component" | grep "Up" | wc -l)

    if [ "$actual_count" -ne "$expected_count" ]; then
        echo "警告: $component 节点数量异常，期望 $expected_count，实际 $actual_count"
        return 1
    else
        echo "正常: $component 节点数量 $actual_count/$expected_count"
        return 0
    fi
}

# 检查节点状态
echo "检查集群节点状态..."
check_component "tidb" 2
check_component "tikv" 3
check_component "pd" 3

# 检查数据同步
echo "检查数据同步状态..."
sync_status=$(mysql -h 127.0.0.1 -P 4000 -u root -e "SELECT COUNT(*) FROM information_schema.TIDB_HOT_REGIONS WHERE progress < 1;" -sN)
if [ "$sync_status" -gt 0 ]; then
    echo "警告: 存在数据同步延迟的 Region"
fi

# 检查慢查询
echo "检查慢查询..."
slow_count=$(mysql -h 127.0.0.1 -P 4000 -u root -e "SELECT COUNT(*) FROM information_schema.CLUSTER_SLOW_QUERY WHERE start_time >= NOW() - INTERVAL 1 HOUR;" -sN)
echo "过去 1 小时慢查询数量: $slow_count"

# 检查磁盘使用
echo "检查磁盘使用..."
disk_usage=$(df /tidb-data | tail -1 | awk '{print $5}' | sed 's/%//')
if [ "$disk_usage" -gt 80 ]; then
    echo "警告: 磁盘使用率 ${disk_usage}% 超过 80%"
fi

# 生成报告
echo "生成健康检查报告..."
report_file="/tmp/health_check_$(date +%Y%m%d_%H%M%S).txt"
{
    echo "TiDB 集群健康检查报告"
    echo "检查时间: $(date)"
    echo "集群名称: $CLUSTER_NAME"
    echo "================================"
    tiup cluster display $CLUSTER_NAME
    echo "================================"
    mysql -h 127.0.0.1 -P 4000 -u root -e "SHOW STATUS LIKE '%TiDB%';"
} > $report_file

# 发送报告
cat $report_file | mail -s "TiDB 健康检查报告" $ALERT_EMAIL

echo "健康检查完成，报告已发送至 $ALERT_EMAIL"
```

## 8. 最佳实践和注意事项

### 8.1 监控最佳实践

#### 8.1.1 告警配置最佳实践

**告警分级策略**：
- **Critical**：影响业务的严重问题，立即处理
- **Warning**：潜在问题，需要关注
- **Info**：信息性通知，用于记录

**告警抑制策略**：
- **时间抑制**：短时间内不重复发送相同告警
- **依赖抑制**：上游故障时抑制下游告警
- **维护窗口**：计划内维护期间暂停告警

**告警升级策略**：
```yaml
# alertmanager.yml
routes:
  - match:
      severity: critical
    repeat_interval: 5m
    routes:
      - match:
          alertname: TiDBNodeDown
        repeat_interval: 1m  # 节点离线更频繁通知
      - match:
          alertname: HighCPUUsage
        repeat_interval: 15m  # CPU 高负载较少通知
```

#### 8.1.2 监控数据保留

**数据保留策略**：
- **Prometheus 数据**：保留 30 天
- **日志数据**：保留 90 天
- **审计日志**：保留 1 年
- **备份文件**：保留 30 天

**存储优化**：
```yaml
# prometheus.yml
storage:
  tsdb:
    retention.time: 720h  # 30天
    retention.size: 50GB  # 最大 50GB
```
